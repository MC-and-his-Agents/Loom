# v0.24.1 Release Readiness

Generated: 2026-07-01

## Scope

`v0.24.1` ships the release post-closeout carrier synchronization flow for #1844:

- #1842 defines the `loom release closeout-sync` command boundary.
- #1843 implements dry-run and apply orchestration for release carrier closeout.
- #1846 covers regression contracts and README / README.zh-CN / CLI matrix documentation.
- #1845 covers version, package metadata, release validation, GitHub Release, npm readback, and closeout.

The release also includes the hosted gate follow-up from #1844: `release closeout-sync` consumes the Loom host-binding PR readback surface instead of calling `gh pr view` directly, and the PR merge gate now emits a focused `head_sha_drift` remediation hint when hosted metadata is stale.

## Boundaries

- `release closeout-sync` is a repo carrier terminalization command, not a publisher.
- Default mode is dry-run. `--apply` only writes repo-local carrier surfaces.
- The command does not create tags, edit GitHub Releases, publish or republish npm packages, merge PRs, or introduce a new carrier or DSL.
- It requires release readback to be published or blocked only by `carrier_not_terminal`; partial, stale, or mismatched release surfaces fail closed.
- The original Work Item suite path is preserved; a release closeout sync does not force `not_applicable`.
