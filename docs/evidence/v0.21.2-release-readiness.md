## Consumed Behavior

- Metadata-only global CLI bootstrap no longer emits `.loom/bin`, bootstrap
  manifest, or generated `Makefile` carriers, and generated locators point to
  `loom ... --target . --json`.
- Root and shared script target resolution honor `LOOM_INVOCATION_CWD` before
  falling back to process cwd.
- `loom pr gate` accepts explicit `--target`, infers `GITHUB_WORKSPACE` in CI
  when omitted, and classifies target/readback failures separately from review,
  spec, or suite gaps.
- `loom merge check/run` accepts explicit `--target`, forwards owner/repo to
  controlled merge, reads statusCheckRollup with `--repo`, and consumes
  metadata-only companion init-result state from the target repository.
- Fact-chain readers fall back from `.loom/bootstrap/init-result.json` to
  `.loom/companion/init-result.json` for metadata-only companion carriers.
- Retained idle workspace/purity reads can consume an explicit retained item
  instead of blocking on an idle active fact-chain.
- Strong governance consumes active ruleset required checks and fails closed
  when ruleset detail reads are unavailable.
- `loom adopt adversarial-test --record` records versioned evidence only after
  adopt verify, runtime parity, and strong maturity pass for the current head.
- `loom gate repair-pr --record` records auditable repair PR evidence without
  mutating GitHub rulesets or bypassing PR gate, controlled merge, review, or
  enforcement readback requirements.
- `tools/check_npm_package.py --surface runtime-copy-parity` now fails closed
  if shared runtime copies drift across `skills/`, `src/skills/`, plugin
  payload, or `.loom/bin`.

Merging the release PR to `main` is publish-capable because this branch changes
`VERSION`, root `package.json`, plugin payload release metadata/hash, runtime
payload files, and release readiness evidence. The expected publish mechanism is
