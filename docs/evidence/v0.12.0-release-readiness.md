# v0.12.0 Release Readiness

This file records the release readiness basis for Loom `v0.12.0`.

It freezes external orchestrator interop as an external-consumer contract:
orchestrators may read Loom Work Items, status, and gates; may attach existing
workspace semantics; and may write back only through the recovery entry fields.
They do not own scheduler state, worker lifecycle, review verdicts, host action
results, gates, or a second status surface.

## Release Inputs

`v0.12.0` release readiness consumes:

- `external-orchestrator-interop`
  - blocking input for the external consumer boundary
- `status-control-plane-v2`
  - blocking input for status and gate provenance reuse
- `orchestration-extension/external-orchestrator`
  - conformance input for fake external orchestrator adoption

## Frozen External Orchestrator Boundary

The release freezes these external orchestrator boundaries:

- read order is init-result locator discovery, Work Item, recovery entry,
  derived status surface, then host mirrors or retained results
- PR-only, tracker-only, release-only, or merge-commit-only entry attempts
  block with the existing gate failure taxonomy
- workspace attach can be consumed, but the external orchestrator must not
  create or delete git worktrees, branches, PRs, or worker lifecycle objects
- recovery writeback is limited to `current_checkpoint`, `current_stop`,
  `next_step`, `blockers`, `latest_validation_summary`, `recovery_boundary`,
  and `current_lane`
- status and gates remain derived from Loom provenance and are never authored
  as external orchestrator truth
- optional external orchestrator declarations are locator-only and cannot carry
  scheduler state, attempt ownership, status truth, review verdict,
  validation summary, host action result, or closeout basis

`v0.12.0` can be tagged and released when:

- the root repository `VERSION` is `v0.12.0`
- all #535 FR and Work Item issues are closed as completed, not deferred

- GitHub tag/release `v0.12.0` points to the validated release commit
- installer tag/release `loom-installer-v0.1.104` points to the same validated

## Remaining Non-Goals

No release blocker remains for external orchestrator interop. This release does
not publish or require a real external scheduler, daemon, tracker polling
product, branch/worktree lifecycle owner, review engine, or second status
surface. Fake orchestrator conformance is the release proof for the external
consumer boundary.
