# v0.24.0 Release Readiness

Generated: 2026-07-01

## Scope

`v0.24.0` ships the single-repo Loom runtime upgrade maintenance flow for #1834:

- #1835 runtime-upgrade maintenance profile and CLI help contract.
- #1836 `runtime-upgrade status` and `runtime-upgrade prepare`.
- #1837 `runtime-upgrade check` and `runtime-upgrade closeout`.
- #1838 version/package/plugin metadata, release validation, GitHub Release, npm readback, and closeout.

The release also includes the README / README.zh-CN command matrix updates, `loom -v` / `loom --version`, and Codex plugin/cache freshness guidance. Repo workflow pin upgrades and user-level Codex plugin/cache refresh remain separate mutation boundaries.

## Boundaries

- No multi-repo batch upgrade mode is shipped in this release.
- `runtime-upgrade prepare` only mutates repository-local maintenance PR state; it does not run `loom host install`, `loom host register`, or edit user-level Codex plugin cache.
- Plugin/cache stale state is advisory by default and must not be written as a repo PR merge fact unless a PR explicitly opts into local runtime/plugin readiness blocking checks.
- The runtime-upgrade path does not bypass review, PR metadata, head binding, hosted checks, release readback, or closeout evidence.

## Validation

Pre-release validation must include:

- `make py-compile`
- `python3 tools/check_cli_contract.py --surface aggregate`
- `python3 tools/check_npm_package.py`
- `python3 tools/check_npm_package.py --surface runtime-copy-parity`
- `python3 tools/check_release_surface.py`
- `python3 tools/loom.py release readback --target . --version v0.24.0 --release-judgment release_required --json`

## Release Readback

Release is complete only after `v0.24.0` tag, GitHub Release, npm package readback, workflow readback, plugin payload metadata, and Loom carrier closeout all agree on the same release commit.
