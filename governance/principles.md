# Governance Principles

本文件定义 Loom 当前最小治理原则。

这些原则来自当前已标记为 `core` 的提取条目：

- `EXT-0001`
- `EXT-0002`
- `EXT-0006`
- `EXT-0023`

## 1. 真相源分层

调度真相与语义真相必须分层存放。

默认要求：

- 调度层负责事项层级、状态、优先级、依赖与关闭语义
- 仓库层负责正式规则、执行工件、风险、验证与恢复上下文

禁止事项：

- 在两个层面并行维护同一份状态真相
- 用仓库文档替代调度层状态
- 用调度描述替代正式契约与执行工件

## 2. 受控执行入口

重要工作不得直接从意图进入代码，必须先进入受控事项。

默认要求：

- 先确定事项类型
- 先明确事项边界
- 再决定进入哪条执行路径

Loom 当前允许的执行入口至少应支持：

- 轻量事项
- 中等事项
- 正式规约事项

## 3. 单一规则落点

同一条规则不得在多个载体中重复完整维护。

默认要求：

- 每条规则必须存在唯一权威落点
- 其他文档只做摘要、映射或引用

禁止事项：

- 在 `AGENTS`、模板、review 文档、流程文档中并行维护同一条完整规则
- 用复制粘贴方式维持“看起来一致”

## 4. 载体职责单一

不同载体必须承担清晰且单一的语义职责。

最小职责分离如下：

- Issue
  - 事项本体、目标、边界、关闭条件
- Project
  - 状态、优先级、阶段位置
- PR
  - 本次改动范围、验证证据、关闭语义
- 执行工件
  - checkpoint、恢复入口、handoff、阻断项

禁止事项：

- 让执行工件承担项目状态真相
- 让 PR 承担长期规范真相
- 让模板承担治理规则真相

## 5. Loom 当前约束

在 Loom 当前阶段，这些原则直接约束后续设计：

- `governance/` 中定义原则
- `harness/` 中定义执行机制
- `templates/` 中定义结构化工件
- `adoption/` 中定义采用路径
- `skills/` 只作为入口层，不替代上述任一真相源
